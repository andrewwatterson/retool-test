# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Retool-native app ("ApplePC Inventory") that browses and edits a personal vintage-computer collection —
~2,400 products and ~10,500 pieces — stored in the `aw.com MySQL` resource, tables `collection_products`
and `collection_pieces`. Source of truth is a Retool app repo (`.retool/app.json` records the app UUID,
host, and the branch/thread this checkout is attached to). The collection was migrated out of Airtable,
which is why `collection_products.uuid` holds Airtable-shaped record ids (`rec` + 14 alphanumerics) and
`collection_pieces.product_id` joins against `uuid`, **not** `id`.

## Commands

Everything runs through the `retool` CLI from the repo root.

```bash
retool check              # regenerate hooks + static checks + tsc + prod builds; exit non-zero on failure
retool check --json       # machine-readable phase results — use this form when iterating
retool check --skip-build # faster: static validation and tsc only
retool start              # background watcher: re-validates on every save until Ctrl-C
retool push -m "…"        # push through the gate to the thread branch; prints the preview URL
retool preview --wait     # fetch/await the current preview URL without re-pushing
retool publish            # publish branch head to the live app
retool resource           # list org resources and the global symbol each is called by
```

Run `retool check` after edits — it is the only local verification available.

### Tests (Playwright, in `tests/`)

There is **no local dev server**: `frontend/hooks/useBackendFunction.ts` is a stub Retool replaces at
build time, so the only runnable copy of the app is the one Retool builds. Specs run against the
preview URL for the current branch, resolved by `playwright.config.ts` calling `retool preview --json`.

```bash
cd tests
npm run auth            # one-time headed login; saves session to tests/.auth/state.json (re-run when it expires)
npm test                # playwright test --project=products
npm run test:headed
npm run report
npx playwright test specs/products.spec.ts -g "hide weak"   # single test
PREVIEW_URL=… npm test  # skip the CLI round trip, or point at a published URL
```

Push before testing — the preview must reflect your changes. Specs run with `workers: 1` against the
**live production database** and are strictly read-only (there is no delete-product backend function).
Assertions are relational ("every visible row matches the filter", "this column is non-increasing"),
never absolute counts, because the data changes.

## Architecture

### Backend: `backend/inventory/*.ts`

Each file is one Retool backend function: a `export default async function name({ params })`. Resource
clients are **injected globals** typed by generated `.d.ts` files under `backend/resources/` (gitignored,
regenerated by `retool check`) — the MySQL resource is `awcomMysql`, called as
`awcomMysql.query<Row>(sql, args)` returning `{ data }`.

Reads: `listProducts`, `searchPieces`, `getProduct`, `getFilterOptions`, `getStats`, `getOrphanPieces`.
Writes: `createProduct`, `updateProduct`, `savePieces`.

Constraints that shape this code, and that new backend code must respect:

- **The push gate rejects any query string interpolated from `params`**, even a whitelisted column name.
  All statement text is precomputed in `_sql.ts` from module constants and passed by reference; call
  sites only supply argument arrays. Multi-row INSERTs and `IN (…)` lists use pre-generated
  variants-by-row-count (`INSERT_PIECES[n]`, `DELETE_PIECES_BY_ID[n]`) with fixed chunk sizes
  (`INSERT_CHUNK = 25`, `IN_CHUNK = 100`). Sort keys/directions go through whitelist maps.
- **Every column in MySQL is `text`**, including `year` — sorting or ranging by year needs
  `CAST(NULLIF(year, '') AS UNSIGNED)`.
- **No index on `collection_pieces.product_id`.** Piece counts must come from a `LEFT JOIN … GROUP BY`,
  not a correlated subquery (measured: 19s vs ~200ms when sorting by piece count). Total row counts ride
  along as `COUNT(*) OVER ()` rather than a second query. Don't wrap join columns in `COLLATE` — it
  disables index use and isn't needed (both columns are `utf8mb4_0900_ai_ci`).
- **Writes are scoped by owner.** `savePieces` SELECTs the product's pieces first, refuses ids belonging
  to another product, and merges partial edits onto current values (an explicit `null` clears a cell; a
  missing key leaves it alone). `createProduct` rolls the product back if the piece insert fails.
- Blank cells are stored as `NULL`, never `''` (`clean()` in `_sql.ts`).
- `'__unset__'` (`UNSET` in the frontend) is the filter sentinel for "field is NULL or empty", so the
  handful of products with no type/completeness stay reachable.

### Frontend: `frontend/`

React 19 + Vite, no router — `App.tsx` switches between four pages with `useState`. `App.tsx` must be
written **last** when creating files, since the dev server resolves imports on each write.

Pages: `Products` (list + right-hand detail pane), `Pieces` (pieces grouped under their product),
`NewProduct`, `Overview` (collection stats + integrity numbers).

Backend functions are called through generated hooks imported from `../hooks/backend/inventory`
(`useListProducts`, `useSavePieces`, …; gitignored, regenerated by `retool check`). The hook exposes
`{ trigger, data, loading, error }` with `data` typed `any` — pages assert it against the hand-written
shapes in `lib/types.ts`. `lib/hooks.ts` wraps the imperative `trigger`:

- `useAutoTrigger(hook.trigger, params)` re-runs on param change and returns `refetch()`, which passes
  `{ skipCache: true }` for after a write.
- `useDebounced(value)` for search boxes.

Filtering, sorting and paging happen in **SQL**, not in the browser.

`components/DataGrid.tsx` is a spreadsheet-like editable grid (cell cursor, range selection, fill-down,
undo, real TSV clipboard parsing in `clipboard.ts` that survives Excel/Sheets quoting). It is controlled:
the parent owns `rows` and applies `onRowsChange`. Both piece grids (`ProductDetail` and `NewProduct`)
use the single shared column set in `components/pieceColumns.ts` — copying a range out of one product and
pasting it into a new one is a primary flow, and it only works while both grids share columns and order.

### Styling

`orgTheme.css` provides Retool org theme tokens as HSL triplets (`hsl(var(--token))`, light + dark);
`app.css` is hand-written CSS on top of them. **There is no `tailwind.config.js` in this checkout, so
Tailwind classes will not compile** — write real CSS. Every selector is `iv-` prefixed to stay clear of
Retool's own styles, and the design bias is density over padding.

The `iv-*` class names double as the Playwright selectors (`tests/products-page.ts` centralizes them);
the app ships no `data-testid`s, so renaming a class can break tests.

## Generated files

`frontend/hooks/backend/**`, `frontend/tsconfig.json`, `frontend/tailwind.*`, `frontend/lib/shadcn/**`,
and `backend/resources/**/*.d.ts` are gitignored and produced by the CLI. Don't edit or commit them; run
`retool check` if they're missing or stale.
